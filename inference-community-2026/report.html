1. 工作负载形态决定胜负：SGLang 在 prefix-heavy / 多轮 / RAG / 结构化输出场景领先 15%-6×；vLLM 在独特 prompt batch + 极限并发稳定性 + 硬件广度上占优。并非 SGLang always wins。

2. 瓶颈不在 kernel，在引擎编排：即使 vLLM 使用与 SGLang 相同的 FlashInfer kernel，仍显著落后。AIMultiple 的洞察："the bottleneck is no longer the mathematical kernel, but the engine's internal orchestration overhead."

3. vLLM 架构迭代极快：双周发布节奏，半年内从 v0.16 → v0.25 共 10 个大版本。MRV2 快速替代 MRV1，PagedAttention 已被删除。

4. SGLang 的 RadixAttention 范式：把 KV cache 视为可复用的"记忆"而非一次性上下文，驱动 prefix caching / multi-turn / multi-layer sharing。HiSparse 进一步将层次化内存管理引入稀疏注意力。

关键定性洞察

  1. GMI (Google AI Overview): 在多轮/RAG中 SGLang 吞吐高出 15-30%，First-Token Latency 低达 40%。但 vLLM 在独特 prompt + 极限并发下延迟更稳定。
  2. Particula (Sebastian Mondragon): "The 29% throughput gap... can shrink to nearly zero on unique-prompt batch jobs, or balloon to 6× on prefix-heavy RAG pipelines." —— 工作负载形态决定胜负。
  3. AIMultiple 最深洞察: "Even when vLLM is optimized with the exact same kernels (FlashInfer) as SGLang, it still significantly trails... the bottleneck is no longer the mathematical kernel, but the engine's internal orchestration overhead."
  4. Runpod benchmark: 多轮对话高并发下，SGLang 稳定 ~30-31 tok/s/req，vLLM 从 22 跌到 16 tok/s。
  5. Spheron 量化: 前缀重叠率须 >60% 才有 SGLang 显著收益；独特 prompt 下两引擎 <5% 差异在误差范围。
  6. Jarvis Labs (May 2026): TPOT/ITL: SGLang 61-63ms vs vLLM ~70ms vs TRT-LLM 更高。使用 dense + MoE 模型, ShareGPT + RULER 16K datasets。
  7. Techsy (Jul 14): 70B scale delta 仅 3-5%；8B scale SGLang +29%；TGI 已于 2025-12 进入 maintenance mode。
  8. DeepSeek V4 officially endorsing SGLang (来源: Particula)。

⚠️ 共识结论：

  • SGLang 在 prefix-heavy / 多轮 / RAG / 结构化输出场景领先 15%-6×
  • vLLM 在独特 prompt batch + 极限并发稳定性 + 硬件广度上占优
  • 并非 SGLang always wins —— 胜率和幅度完全依赖 prefix overlap ratio

🌿 SGLang 架构与设计哲学

核心设计哲学

"KV radix tree as the first-class abstraction" vs vLLM 的 "block-based KV cache as fixed page"

  • RadixAttention 把 KV cache 视为可复用的"记忆"而非一次性上下文
  • 动态树形复用 (dynamic tree-shaped reuse) vs 固定大小块复用 (fixed-size block reuse)
  • 调度策略：continuity-aware vs longest-prefix-match
  • SGLang 选择不做 LLM 框架，而是做 serving system

HiSparse: 层次化内存管理

SGLang 最新工作 (2026-04-10)：HiSparse 通过将不活跃的 KV cache 条目主动卸载到主机内存，显著降低 GPU 内存压力，同时在 GPU HBM 上维护热设备缓冲区。

  • 核心机制: 专用 CUDA kernel 识别 top-k cache misses，LRU 驱逐策略，更新页表并从主机获取所需条目
  • 性能: GLM-5.1-FP8 在 32K-input, 8K-output 场景下，256 并发请求达到基线 3× 以上 吞吐提升，长上下文场景最高 5×
  • 适用模型: 目前支持 DeepSeek Sparse Attention (DSA) 模型族，包括 DeepSeek-V3.2 和 GLM-5.1
  • 未来方向: 扩展至混合模型 (hybrid models)，利用 Grace Blackwell 更高 CPU-GPU 带宽

🔀 关键架构分歧点

1. KV Cache 管理策略的根本分歧

vLLM 的 PagedAttention 将 KV cache 视为固定大小的物理页，通过页表映射实现高效内存管理。SGLang 的 RadixAttention 则将 KV cache 视为可复用的前缀树，天然支持 prefix caching 和多轮对话。

关键洞察: vLLM v0.25 删除 PagedAttention 标志着向 MRV2 统一后端转型，但底层仍然是 block-based 思维。SGLang 的 radix tree 在 prefix-heavy 场景下的优势正是来源于此。

2. Disaggregated Prefill 架构差异

vLLM 通过 NIXL 框架实现了成熟的 PD disagg，支持异构 TP/block_size/KV layout。SGLang 则通过与 Mooncake、NVIDIA Dynamo 的集成实现 KV cache 的分布式管理。

关键洞察: vLLM 走的是"自研核心框架"路线，SGLang 走的是"生态集成"路线。两者在 PD disagg 上的工程路径反映了不同的设计哲学。

3. 调度器设计哲学

vLLM 的 async scheduling 追求最大化 GPU 利用率 (30.8% throughput)，通过 zero-bubble 和 PP bubble elimination 减少空闲。SGLang 的 continuity-aware 调度则优先保证 prefix cache 的连续性。

关键洞察: vLLM 优化的是"管道效率"，SGLang 优化的是"缓存命中率"。这直接解释了两者在不同工作负载下的性能差异。

4. 前端与运行时

vLLM 已用 Rust 重写前端 (production ready)，追求极致的 API 吞吐和稳定性。SGLang 仍以 Python 为主，灵活性更高但运行时开销更大。

关键洞察: vLLM 的 Rust frontend 是其"引擎编排开销"缩减的关键一步——这正是 AIMultiple 指出的 vLLM 传统劣势所在。

🎯 关键结论与战略建议

1. 没有"万能引擎"——工作负载决定选择

对于推理系统架构师：

  • Prefix-heavy / 多轮 / RAG 场景 → SGLang 是明确选择 (15%-6× 优势)
  • Unique-prompt batch / 极限并发 / 多硬件 → vLLM 更合适
  • 建议建立双引擎策略，根据工作负载动态路由

2. vLLM 的 Rust Frontend 将缩小编排开销差距

AIMultiple 指出的"引擎编排开销"是 vLLM 的传统劣势。Rust frontend 的 production ready 化是 vLLM 对此的直接回应。2026 下半年 v0.25+ 的性能数据将验证这一改进的实际效果。

3. PD Disaggregation 是 2026 下半年的核心战场

两个引擎都在 PD disagg 上投入重兵。vLLM 的 NIXL 框架已相当成熟，SGLang 通过 Mooncake/Dynamo 集成紧随其后。KV cache 的分布式管理将是下一代推理基础设施的核心能力。

4. 层次化内存管理是长上下文推理的必须路径

SGLang 的 HiSparse 证明：通过将不活跃 KV cache 卸载到主机内存，可在长上下文场景实现 3-5× 吞吐提升。这一方向与 vLLM 的 multi-tier KV offload 殊途同归。

5. 芯片设计启示

两个引擎的演进方向对下一代加速器 (NPU/ASIC) 的启示：

  • KV cache 管理需要硬件级支持 (页表/树形结构)
  • CPU-GPU 带宽是关键瓶颈 (Grace Blackwell 等平台将受益)
  • 稀疏注意力需要层次化内存系统的配合
