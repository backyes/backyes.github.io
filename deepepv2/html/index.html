DeepGEMM & DeepEP 架构分析

基于博客《GPU微架构第三性原理：DeepEP的第一性原理》的三向对比分析 — 博客理论 ⇔ DeepEP源码 ⇔ DeepGEMM源码

核心发现

从 DeepEP 到 Mega MoE 的架构演进本质：

  • 同步范式：Barrier (DeepEP) → mbarrier FIFO (DeepGEMM)
  • 通信模型：消息传递 Send→Forward→Receive → Load/Store 对称内存直传
  • 数据布局：5层Buffer → 4层 → 3层，Chunk和Dispatch Buffer依次消除
  • 执行模式：双模式(Normal/Low-Latency) → 单融合Kernel
  • 设计哲学：让计算适配通信 → 让通信适配计算

  • 05_01_dispatch_combine Dispatch/Combine 融合
    博客3步变换(Token→Destination→Expert)在Mega MoE坍缩为1步，Destination-major缓冲区被消除
  • 05_02_buffer_symmbuffer Buffer 系统 → SymmBuffer
    10段式SymmBuffer布局，范式从Push→Pull转变，无Dispatch/Chunk Buffer
  • 05_03_warp_specialization Warp Specialization
    16 warps per CTA分工(Dispatch/TMA/MMA/Epilogue)，Send→Pull范式转变，显式寄存器重分配
  • 05_04_fifo_pipeline FIFO 流式流水线
    mbarrier-based producer-consumer协议替代显式FIFO，per-token粒度流式处理

    两阶段Count-Scatter避免contention，TokenSrcMetadata结构，权重前移创新
  • 05_06_nvlink_rdma NVLink/RDMA 对称内存
    Symmetric Memory消除三阶段流水线，Load/Store语义替代消息传递
  • 05_07_normal_vs_lowlatency Normal vs Low-Latency
    Mega MoE不存在双模式区分，单一Training导向内核，单极演化
  • 05_08_evolution_deepep_to_megamoe DeepEP→Mega MoE 演进
    单Kernel MoE融合Dispatch→Linear1→SwiGLU→Linear2→Combine，L1→L2不经过HBM
  • 05_09_chunk_streaming Chunk Streaming
    Mega MoE超越Chunking，Symmetric Memory使Token级通信高效，让通信适配计算
  • 05_10_counting_sort Counting Sort / Bucketization
    GPU inline Count→Prefix Sum→Scatter，两级atomic策略，同时服务通信+计算
