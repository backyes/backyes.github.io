Deploying DeepSeek on GB200 NVL72 with PD and Large Scale EP (Part I): 2.7x Higher Decoding Throughput
The SGLang Team
June 16, 2025

HIGHLIGHTS:
- 7,583 tokens per second per GPU for decoding on GB200 NVL72
- 2.7x speedup compared to H100 per GPU for 2,000-token input lengths

METHODS:
- Blackwell DeepGEMM: FP8 precision GEMM for Blackwell, UMMA feature for fast matrix multiplications
- Blackwell DeepEP: NVLink-only environment support, mapping remote GPU memory to local virtual address space; 15% performance improvement
- FlashInfer Blackwell FMHA: Fused Multi-Head Attention for prefill
- Blackwell CUTLASS MLA: leverages UMMA, 2-SM cluster mode for TMA, reducing L2 read traffic on KV cache
- Blackwell Mooncake: KV cache transfer engine for PD disaggregation, NVLink support

EXPERIMENTS:
- 14 nodes in GB200 NVL72; 12 nodes for decode, 2 for prefill (mimics 6P/12D in 18-node deployment)
- 2.5-3.4x speedup across various sequence lengths

KEY FACTORS:
1. Enhanced Memory Bandwidth and Computation Power (HBM bandwidth, FLOPS)
2. Larger Memory Capacity → Larger KV cache → Larger batch sizes → improved kernel efficiency
   - Combined with kernel speedup, still meets ITL requirements
3. Larger NVLink Domain: pure-NVLink (no RDMA needed) → lower communication latency
   - Allows two-batch overlap to be DISABLED (avoids waste when communication > computation)
4. PD + Large-scale EP: flexible decoupling, reduces memory access pressure

ABLATION STUDY: BATCH SIZE
- Larger batch sizes boost throughput
- GB200 NVL72 faster than H100 at same batch size
- Input/output lengths: 2000/100

LIMITATIONS / FUTURE WORK:
- Small batch sizes (single node) suboptimal
- Prefill performance next focus
- Latency optimizations pending
- Kernels not saturating memory bandwidth
- Communication overlap needs adjustment for NVLink
- MTP beneficial especially when batch size too small
