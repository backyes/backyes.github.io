SSL/TLS 控制面加密

URPC 支持基于 OpenSSL 的控制面加密：

  • 通过 urpc_ssl_config_set 配置 SSL 参数（PSK 模式或证书模式）
  • 支持 TLS 1.2 / TLS 1.3
  • 可配置 cipher list 和 cipher suites
  • Server 和 Client 各自维护 SSL 上下文

扩展机制（Ext Ops）

URPC 提供 ext_ops_t 扩展接口，允许用户自定义：

// dp.h: ext_ops_t
typedef struct ext_ops {
    int (*rx_req_process)(ext_call_ctx_t *, req_ctx_t **, urpc_poll_msg_t *);
    int (*tx_read_process)(ext_call_ctx_t *, urpc_poll_msg_t *);
    int (*tx_read_err_process)(ext_call_ctx_t *, urpc_poll_msg_t *);
    void (*ext_proto_fill_extra_info)(urpc_req_head_t *, queue_local_t *, queue_remote_t *);
    bool (*timeout_create_process)(urpc_call_wr_t *, req_entry_t *);
    int (*encrypt)(urpc_hdr_type_t, urpc_cipher_t *, urpc_sge_t *, uint32_t);
    int (*decrypt)(urpc_hdr_type_t, urpc_cipher_t *, urpc_sge_t *, uint32_t);
    int (*stream_send_process)(void *, uint32_t, uint32_t, uint32_t);
    int (*rx_rsp_process)(ext_call_ctx_t *, urpc_poll_msg_t *);
} ext_ops_t;

Token 策略

UMQ 实现了可选的 token 策略（UMQ_FEATURE_ENABLE_TOKEN_POLICY）：

  • 启用时，Jetty 和 segment token 通过 urpc_rand_generate 生成随机值
  • 禁用时，使用 get_timestamp() 作为 token（低安全场景）
  • Token 在 bind 信息交换时传递给对端，确保只有持有正确 token 的远端能访问本端内存

Conclusion

URPC 在 UB 总线上构建了一套完整的"从硬件原语到函数调用语义"的技术栈。通过本次深度代码分析，我们揭示了以下关键洞察：

  • 分层抽象：URMA → UMQ/URPC Framework → 公共 API，每层只关注本层职责，通过 ops 接口实现多态
  • 带内控制：利用 immediate 数据编码流控、内存导入、反向拉取等控制协议，不占用数据通道
  • 并发安全：tx_ctx 双次释放、req_entry hash+线性探测、读写锁分离等精细并发控制
  • 资源复用：JFR/JFC 通过 ref_cnt 在多个队列间共享
  • 用户可选：每一层增量功能都是可选的（feature flag），适应不同场景
  • 生产级特性：Keepalive、DFX、SSL/TLS、300K 并发 Channel

从架构视角看，URPC 的设计遵循了"分层抽象、带内控制、用户可选"的原则——既能以最小开销运行在延迟敏感的推理场景，也能以全功能模式运行在需要流控和加密的训练/存储场景。
