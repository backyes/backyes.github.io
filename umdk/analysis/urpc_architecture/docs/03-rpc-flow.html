Server 端：返回 RSP

// dp.c: urpc_func_return()
int urpc_func_return(uint64_t urpc_qh, void *req_ctx, urpc_return_wr_t *wr, ...) {
    // 1. 获取 queue 和 req_ctx
    l_queue = (queue_t *)urpc_qh;
    ctx = (req_ctx_t *)req_ctx;

    // 2. 分配 tx_ctx
    tx_ctx = queue_ctx_get(l_queue, QUEUE_CTX_TYPE_TX);

    // 3. 填充 RSP 协议头
    rsp_head = (urpc_rsp_head_t *)rsps[0].addr;
    urpc_rsp_fill_basic_info(rsp_head, status, client_channel, ack);
    urpc_rsp_fill_one_req_info(rsp_head, req_id, response_total_size, option);

    // 4. 发送 RSP
    l_queue->ops->send(l_queue, &queue_wr);
}

tx_ctx 生命周期（双次释放机制）

URPC 使用 tx_ctx_try_put() 实现双次释放：tx_ctx 必须经历两个"完成事件"才能被释放回 slab：

flowchart TB N0[tx_ctx_t *ctx] N1[ctx->free_events_completed == FALSE] N2[QUEUE_CTX_TYPE_TX, ctx]

这解决了 TX CQE 和 ACK/RSP 并发到达时的竞态条件——无论哪个先到，都必须等两个都完成。
