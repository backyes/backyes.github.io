核心发现

三视角共识 · 源码级关键架构洞察
  • Token 重组不可避免：MoE routing 的随机性决定了接收端必须将乱序 token 重排为 expert-contiguous 布局——这不是设计选择，而是 GEMM 内存连续性需求的数学必然。
  • Dispatch 随机访存是数学必然：每个 token 独立选择 expert，目标地址不可预测，预取准确率仅 ~0.4%。任何预取策略的准确率上限为 K/E = 3.1%。
  • Combine 可顺序执行：利用 dispatch 阶段保存在 recv_src_metadata 中的 routing 信息，combine 只需逆序遍历即可还原，无需随机访存。
  • 层次化带宽利用：NVLink（~726 GB/s）vs RDMA（~90 GB/s）的 ~8x 差距决定了 Hybrid mode 的分层设计——域内全带宽、域间受限带宽。
  • SM 最小化（4x 节省）：通过 TMA 硬件卸载数据搬运 + warp 特化三角色流水线，将通信占用从 24 SM 降至 4-6 SM，释放计算资源给 GEMM。
  • GPU-Initiated RDMA 零 CPU 开销：V2 使用 NCCL Gin backend 实现 GPU warp 直接发起 RDMA put，消除传统 RDMA 的 CPU 代理开销，实现 kernel-level all-to-all。
  • 统一编址是 fast path 而非 only path：NVLink TMA 零拷贝直写依赖对称指针机制，但 RDMA fallback 路径（gin.put）已证明功能完备性——编址是性能优化而非功能必须。
  • Expand Mode 以空间换时间：每个 token 为每个 top-k expert 独立分配 slot（K 倍内存），将 sparse-to-dense 转换提前到 dispatch 阶段，使下游 GEMM 可直接使用连续内存。
