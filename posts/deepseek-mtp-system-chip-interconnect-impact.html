DeepSeek MTP 对计算系统、芯片和互联的结构性影响

📅 2026-07-31
DeepSeekMTPMulti-Token-Prediction芯片超节点互联算力密度LPXKV-Cache

核心判断

MTP (Multi-Token Prediction) 正在改变推理负载的算力强度画像——从"访存密集型"向"计算密集型"回归。这一转变的深远影响不在于单次推理成本下降，而在于它重构了芯片、互联、存储三层基础设施的投资回报结构。

DeepSeek 还是高端选手，有意志力的选手——坚持高性价比，找最高成本突破口走，坚持普惠人类的技术。

1. 算力芯片：计算与 KV-Cache 比例的反转

MTP 的核心效应是提高计算量与 KV-Cache 访存量的比例。

传统推理（特别是长序列 decode）是典型的 memory-bound 负载——每个 token 的计算量小，但需要频繁访问巨大的 KV-Cache。MTP 让每个 decode 步骤预测多个 token，本质上是在同一份 KV-Cache 上摊更多的计算。

维度传统 DecodeMTP Decode (k步)
每 token 计算量1× FLOPs≈k× FLOPs
KV-Cache 访存量1×1×（共享）
算力强度 (FLOPs/Byte)低线性增长

定性结论：

  • 算的越来越接近训练——推理负载的算力强度曲线向训练方向偏移
  • 如果 MTP 预测步数 k 持续增长，算力强度的天花板理论上比训练还要高（因为 MTP 的多步梯度路径比单步更长）
  • 具体天花板取决于 MTP 的实际部署长度——$k$ 越大，对计算单元的压力越大

这意味着：推理芯片的算力利用率瓶颈，正在从 HBM 带宽转向片上计算能力。

2. 通信范式：低时延 vs 高带宽的分叉

MTP 对通信的影响不是单向利好，而是按 MTP 规模产生结构性分叉：

MTP 规模利好方向利空方向
小 MTP大超节点（低时延语义）—
大 MTP超节点大带宽、UB 高带宽低时延通信机制

具体拆解：

  • 大 EP（Expert Parallelism）利好低时延——EP 的小粒度 All-to-All 对时延极度敏感，MTP 增加的计算时延会放大 EP 的同步开销
  • 大 MTP 利好 UB 高带宽——统一带宽（UB）天然驾驭大块数据传输，MTP 的大计算块正好匹配
  • 不利好低时延通信机制——MTP 的"计算换访存"逻辑让低时延互联的边际收益下降
  • 不利好硬件直驱的高代价直驱软件——这类方案假设访存是唯一瓶颈，MTP 打破这一假设后 ROI 下降
  • 利好传统通信范式——传统通信栈也能驾驭高带宽场景，不必为极致低时延付出额外代价

拐点在哪？ 取决于 MTP 的两级规模——小 MTP 和大 MTP 对通信的要求截然不同，拐点位置由具体部署的 MTP 步数和并行策略共同决定。

3. 超节点域：从"均摊 Weight"到"大块通信"

理解超节点域的影响，需要先理解大 EP 的本质：

大 EP 的本质是均摊 Weight 的 HBM 加载带宽——通过将专家分布到更多节点，每个节点只需加载部分 Weight，从而降低单节点的 HBM 带宽压力。

MTP 对这一逻辑的影响链：

MTP ↑ → 计算强度 ↑ → 单节点 HBM 带宽压力 ↓
→ 大 EP 的"均摊 Weight"收益被抑制
→ 瓶颈从 HBM 转向通信
→ 通信形态变为"大块通信"
→ 利好小超节点域的高带宽

关键推论：

  • 大 EP 对 MTP 场景的边际收益递减——当计算不再是瓶颈时，为了 EP 而额外付出的通信开销不再划算
  • 瓶颈转向通信，但是大块通信——大块通信天然利好高带宽互联
  • 利好"小超节点域"的高带宽——不是跨数据中心的大范围互联，而是机柜内/相邻机柜的高带宽域

4. 专有芯片：LPX 等流芯片的市场抑制

LPX 这类流芯片会受到市场抑制，大概率会很麻烦。

根本原因：LPX（以及 Groq/Trillium 等 SRAM 架构）的核心设计假设是——通过大容量片上 SRAM 消除片外访存瓶颈。SRAM 架构天然优化了"计算靠近数据"的访存模式。

但 MTP 正在打破这个假设：

LPX 设计假设MTP 后的现实
访存是唯一瓶颈计算强度上升，访存不再是唯一瓶颈
SRAM 大容量 = 优势SRAM 容量固定，无法随 MTP 计算需求线性扩展
确定性低时延有价值低时延边际收益下降

SRAM 架构优化访存的假设在打破——当负载从 memory-bound 转向 compute-bound，SRAM 的带宽优势被稀释，而 SRAM 的面积/功耗劣势被放大。

这不是说流芯片完全失去价值，而是说MTP 压缩了流芯片的市场窗口——如果这个架构还没规模化落地，MTP 可能让它再次夭折。

5. 片上介质：国产存储与中端工艺的契机

MTP 对片上介质的影响是去高端化的：

  • 利好国产存储等介质——当访存不再是唯一瓶颈时，对 HBM 极端带宽的依赖下降，国产存储介质有了上桌竞争的窗口
  • 利好中端工艺——compute-bound 负载对晶体管密度的依赖低于 memory-bound 负载对 HBM 带宽的依赖
  • 不利好高 HBM 带宽高端工艺——HBM 带宽的边际收益下降，为极致 HBM 带宽支付溢价的合理性减弱

大家都能上桌竞争了。

这是一个结构性的市场重塑——过去几年 HBM 生态的垄断溢价，正在被 MTP 的"计算换访存"逻辑侵蚀。

6. 算力密度：加速堆叠与 HBM 的新一轮循环

MTP 对算力密度的影响分两个阶段：

短期（1-2 年）：算力密度加速堆叠

一旦访存墙被打破，算力密度更容易堆叠——不再受制于"每瓦算力对应 X GB/s HBM 带宽"的 Roofline 约束，可以更激进地堆叠计算单元。

中期（2-3 年）：进入下一个 HBM 增长周期

算力密度翻倍后，访存还是问题。这是一个循环：

访存墙被打破 → 算力密度堆叠 → 计算能力翻倍
→ 新的访存需求产生 → 访存再次成为瓶颈
→ 强化 HBM 需求 → 新一轮 HBM 增长周期

MTP 不会消灭访存墙，只是让访存墙在更高的算力水平上重新出现。

7. 访存不是问题了？这是一个常见误区

市场上有一种观点认为"MTP 让访存不再是问题"——这是误区。

核心逻辑：

  • MTP 短期内确实降低了访存压力（同等 KV-Cache 上摊更多计算）
  • 但算力密度会更快地增长——应用层面会迅速吃掉节省出来的算力
  • 1-2 年后，访存需求会再次强化——不是因为 MTP 失效，而是因为算力增长超过了 HBM 带宽增长

MTP 不是访存墙的终结者，而是访存墙的延迟器——它把问题推后了，但没有取消它。

8. 片外介质：DDR 的可能利好

对片外介质的影响存在一个反直觉的可能：

DDR 这类介质可能反而是利好的。

逻辑链：

  • MTP 让计算强度上升 → 对 HBM 极端带宽的依赖下降
  • 但模型总容量需求不变（甚至因长序列而增加）
  • 如果 HBM 容量成为瓶颈，DDR 作为容量层的重要性上升
  • 推理系统可能从"HBM only"转向"HBM + DDR"混合存储架构

这不是确定性判断，而是一种结构性可能——MTP 改变了存储层级的边际替代率，让 DDR 这类"大容量、低带宽"介质在新的成本结构下找到位置。

9. Token 成本与序列长度的加速演进

MTP 对 token 成本和序列长度的影响：

维度当前（2026 中期）预测（2027）
推理 token 成本基准成倍下降
主流序列长度256K 量级2M 甚至更大

MTP 通过提高算力利用率直接压低 token 成本，而成本下降会间接刺激序列长度成倍增长——更便宜的 token 意味着用户愿意消费更长的上下文。

长期趋势不变，但节奏加快：

  • UB 低时延 ✓
  • 高带宽 ✓
  • 高 HBM ✓
  • 低时延互联 ✓
  • 超长序列 ✓

这些方向都不会变，只是可能越来越快了。

10. 路线之争：为什么 Kimi3 无法 Scaling Cost

文章最后回到模型架构路线的宏观判断。

扩展百万序列有两条路线：

路线代表记忆成本计算成本驾驭多层介质
线性注意力Kimi3 (KDA)线性（但隐含指数记忆衰减）线性 + Full Attention✗
稀疏注意力DeepSeek V4 (DSA)稀疏可控稀疏可控✓

Kimi3 的核心问题：线性 + Full Attention 的混合，仍然是指数级的记忆成本和计算成本。

  • 线性注意力虽然理论上是 O(1) 状态，但有效记忆容量随序列长度指数衰减（遗忘门的信息损失累积）
  • 为了弥补这一点，Kimi3 保留了 1/4 的 Full Attention，这 1/4 Full Attention 在大序列下仍然是平方级成本
  • 无法驾驭多层介质来系统性降低成本——这是模型结构决定的，不是工程优化能解决的

只有稀疏才能 scaling storage/memory cost。

Kimi 去年底的技术报告其实也解读了——他们也认为后面应该要融进稀疏路线。只是 Kimi3 的产品化路径选择了先走线性注意力。

DeepSeek 的选择不是偶然——它代表了一种系统设计方法论：找到成本结构中最贵的环节，用算法创新去突破，然后让市场跟随。相比 Kimi3 的"堆精度"路线，DeepSeek 在系统设计方法上还是差很多。
